# Domain documentation

Use a single-context layout: `GLOSSARY.md` at the root and decisions under `docs/adr/`.

Before relevant exploration, read existing glossary entries and related decisions. Use established terms consistently and surface conflicts with existing decisions. If these files do not exist, continue; do not create empty scaffolding. Add entries or decisions only when a meaningful term or decision has been established and writing is authorized.

Existing topic notes retain their current organization. Preserve uncertainty, limitations, and links to source or experimental evidence. Do not present AI-generated explanations as demonstrated learner mastery. Do not automatically move Lab experiments into this repository or add RTOS mechanisms to the MP3 project.
