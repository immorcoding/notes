Three small tools

Lesson 2 · ~15 minutes · Goal: know exactly when to use /wait-what, /wizard and /to-questionnaire, and see them in embedded, game and video work.

Recall first

From lesson 1: in one line each, what problem does each of these three skills solve? Write it before you read on.

All three are standalone: not steps in the main flow. You use them at any moment, inside any other work. A quick way to tell them apart is to ask where the blocker is:

The blocker is…Use
In your understanding: the agent lost you/wait-what
In your hands: only a human can click or plug it in/wizard
In someone else's head: they know, you don't/to-questionnaire

1 · /wait-what

What it is. The whole skill is three lines. It tells the agent: "I don't understand where you've got to. Re-pitch that: give a little context, use ASD-STE100 Simplified Technical English, and use the words from GLOSSARY.md."[1]

Why the name matters. "Be concise" or /tldr describes the output, so the model clips words and gets blunter. "Wait" describes your state, so the model backs up and adds the premise you missed. Shorter and clearer.[1]

  • User-invoked only. Only you know when you stopped following.
  • It re-pitches "that", not "the last message": the agent decides how far back to go.
  • No GLOSSARY.md? It still works, but you lose the project-vocabulary half. (Your notes repo has none yet.)
  • It fixes one message. The upfront cure is /grill-with-docs, which builds the shared words.

In your fields (my examples, not Matt's)

EmbeddedThe agent explains tickless idle with "suppress ticks, reprogram LPTIM compare, fix up xTickCount via step-tick, BASEPRI gating…". /wait-what gets you the premise first: why the tick is stopped at all.
GamesA reply about "archetype chunks, structural changes and sync points" in an ECS. A glossary that defines entity, component, system makes the re-pitch use your words.
Video"Long-GOP proxies hurt scrubbing; go intra-frame." The re-pitch should say what a GOP is and why your editor stutters, in one short paragraph.

2 · /wizard

What it is. The agent writes an interactive bash script; you run it. The script goes one stage per screen: opens a URL, says what to click, captures the value (secrets typed hidden), writes it to .env or GitHub secrets/variables, and asks for confirmation before anything irreversible.[2]

  1. Scope: reads .env*, README, CI secrets.* references; shows you the stage list to confirm.
  2. Map: exact click path per stage. If it doesn't know the UI, it asks: never invents.
  3. Author: copies template.sh, writes only the stages. The library above the STAGES marker is never edited.
  4. Verify: bash -n, shellcheck, static trace. It never runs it end to end: your first run is the test.

A stage looks like this (from Matt's template):

stage "Stripe: API keys"
open_url "https://dashboard.stripe.com/test/apikeys"
step "Click 'Reveal test key' on the Secret key row, then copy it."
ask_secret STRIPE_SECRET_KEY "Paste the secret key:"
write_env STRIPE_SECRET_KEY "$STRIPE_SECRET_KEY"
set_secret STRIPE_SECRET_KEY "$STRIPE_SECRET_KEY"   # CI needs this one
  • Model-invoked: the agent reaches for it on its own when it hits a step only you can do, instead of dumping six steps into chat.
  • Keys you type into the script never enter the model's context. Keys you paste into chat do.
  • No back button: Ctrl-C and re-run. Saved values come back as defaults.
  • Ephemeral by default. Commit it only if the next person will need the same setup.
  • It's bash: on Windows, run it in Git Bash or WSL.

In your fields (my examples, not Matt's)

EmbeddedBringing up a new board: "set BOOT0 jumper", "plug in ST-Link", "power-cycle" as pure-action stages; capture the COM port into .env; put a confirm gate before changing option bytes or readout protection, which is hard to undo.
GamesStore/CI release setup: create the app and depots in a store's partner dashboard, capture the IDs as GitHub variables, the build-upload account as a secret, so CI can push builds.
VideoWiring an upload pipeline: create an OAuth client in a cloud console, capture client ID (variable) and secret (secret); or a one-off archive move where "delete the old bucket" sits behind a confirm.

Physical steps can't be verified by the script; it can only ask you to confirm them. That's still better than instructions scrolling away in chat.

3 · /to-questionnaire

What it is. It writes a Markdown questionnaire for one person who holds knowledge you lack. Fill-in async, or go through it together in a meeting.[3]

The key move: grill the send, not the subject. It asks you only two things, then stops:

  1. Who is it going to? Role, expertise, relation to you: sets tone and how much context to include.
  2. What do you need back? The decisions or facts you can't settle alone: becomes the checklist.

Then it writes to-questionnaire-<slug>.md in the current folder: purpose, short context, how to answer ("I don't know" is welcome), themed questions most-important-first, one idea per question, and a closing "anything else?". It does not send it anywhere.

  • One recipient per run. Three experts → three runs.
  • Flat list, not branching.
  • Best run in the same conversation as a stalled grilling session, so it can draw on it.
  • Bring the answers back into /grill-with-docs or /to-spec.

In your fields (my examples, not Matt's)

EmbeddedTo the hardware engineer: card-detect pin polarity, which DMA streams are free, max SPI clock the layout allows. You can't read these from code.
GamesTo the game designer: what happens on death mid-quest, is save anywhere or checkpoint-only. Business rules the code must follow but you shouldn't guess.
VideoTo the client or director: delivery resolution and frame rate, colour space, loudness target, which shots are locked. A guess here means a re-render.

Practice

Mixed on purpose. Some answers are none of today's three.

Try it for real

Pick one, today, on real work:

  • Next time I lose you mid-explanation, type /wait-what and judge it: shorter and clearer, or just blunter?
  • Think of a question your notes are stuck on that only someone else can answer (a board designer, a colleague, a forum expert). Run /to-questionnaire for that one person.
  • Next time setup needs dashboard clicks or hardware steps, ask for a wizard instead of a list.
