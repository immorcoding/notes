# 中断运行机制
## 1. 中断响应过程
1. **外设事件发生**：<br>
   外设事件发生后（如 UART 接收到数据），外设会在相应的状态寄存器中设置标志位（例如 USART 的 RX 标志位）。该标志位属于外设自身，通常为一个 bit，用于表示某个事件是否发生，***不属于 NVIC***。如果外设对应的中断使能位（例如 RXNEIE）已经打开，则外设向 NVIC 发出 IRQ Request。<br><br>
2. **中断请求进入 NVIC**：<br>
   NVIC 收到 IRQ Request 后，对应异常可以进入 **Pending（挂起）状态**，表示该异常已经产生并等待 CPU 处理。***Pending 并不代表 CPU 会立即进入 ISR，即使当前中断被屏蔽或有更高优先级异常正在执行，该异常仍可能保持 Pending。***<br>
   NVIC/内核随后根据以下条件判断该 Pending 异常能否被响应：<br>
   - 对应 IRQ 是否在 NVIC 中 Enable（如 NVIC_ISER 对应位）
   - 是否受到 PRIMASK、BASEPRI 等屏蔽
   - 当前正在执行的异常优先级
   - Pending 异常自身的优先级<br>
   > 注意：NVIC 中断使能位与外设内部中断使能位是两个不同层级的开关。<br><br>
3. **Cortex-M 开始 Exception Entry**：<br>
   当某个 Pending 异常已经使能且优先级满足响应条件时，Cortex-M 开始 Exception Entry（异常进入）。在异常发生前，如果是裸机程序，Thread Mode 通常使用 **MSP**；如果是 FreeRTOS 任务，Thread Mode 通常使用 **PSP**。<br><br>
4. **Cortex-M 硬件自动保存现场**：<br>
   Cortex-M 自动将 **R0~R3、R12、LR、PC、xPSR** 保存到异常发生前正在使用的栈中。裸机通常压入 MSP 栈，FreeRTOS 任务通常压入当前任务的 PSP 栈。***这里应理解为硬件形成固定的异常栈帧布局，而不是软件逐条执行 PUSH。***<br>
```text
高地址
0x20000FFC  xPSR
0x20000FF8  PC
0x20000FF4  LR
0x20000FF0  R12
0x20000FEC  R3
0x20000FE8  R2
0x20000FE4  R1
0x20000FE0  R0   ← 异常后的 SP
低地址
```
5. **进入 Handler Mode 并跳转到 ISR**：<br>
   Cortex-M 根据中断向量表（Vector Table）取得对应 ISR 的入口地址，并将其加载到 PC，开始执行 ISR（例如 `USART1_IRQHandler`）。同时 CPU 进入 **Handler Mode**，Handler Mode 固定使用 MSP。当前 LR 被设置为特殊值 **EXC_RETURN**，不再是普通函数返回地址；原程序的 LR、PC、xPSR 已经保存在异常栈帧中。对应异常由 Pending 转为 **Active**。<br><br>
6. **ISR 判断并处理中断来源**：<br>
   一个外设 IRQ 可能对应多个中断来源，因此 ISR 通常需要读取外设状态寄存器判断具体原因，例如 RX、TX、IDLE、错误等，然后执行对应的处理逻辑。<br><br>
7. **清除中断源**：<br>
   ISR 根据外设规定的方法清除或处理对应中断标志。不同外设的清除方式可能不同，例如写特定位清除、读取数据寄存器后自动清除、写 ICR 清除等。***如果中断源一直没有清除，外设可能持续产生 IRQ Request，导致 ISR 退出后立即再次进入。*** HAL 中常见的回调函数属于软件框架设计，并不是 Cortex-M 中断机制本身的一部分。<br><br>
8. **ISR 结束并开始 Exception Return**：<br>
   ISR 执行完成后，通过 LR 中的 **EXC_RETURN** 触发 Exception Return（异常返回）。EXC_RETURN 中包含异常返回所需的信息，例如返回 Thread Mode 还是 Handler Mode、使用 MSP 还是 PSP 恢复异常栈帧等。<br><br>
9. **恢复异常现场**：<br>
   Cortex-M 根据 EXC_RETURN 选择正确的栈，并自动恢复之前保存的 **R0~R3、R12、LR、PC、xPSR**。由于 PC 也被恢复，因此 CPU 可以继续执行异常发生前的程序。<br>
   - 返回 **Thread Mode**：恢复之前被中断的普通程序或 RTOS 任务。
   - 返回 **Handler Mode**：通常表示恢复之前被更高优先级异常抢占的 Handler。
   - 如果异常返回时还有满足条件的 Pending 异常，Cortex-M 可能通过 **Tail-Chaining（尾链）** 直接进入下一个 Handler，而不进行完整的出栈再入栈过程。<br><br>
10. **回到原程序继续运行**：<br>
    Cortex-M 根据恢复后的 PC 继续执行被中断程序。裸机程序通常恢复到使用 MSP 的 Thread Mode；FreeRTOS 任务通常恢复到使用 PSP 的 Thread Mode。如果 ISR 导致了更高优先级任务就绪，FreeRTOS 还可能触发 PendSV，在异常退出路径上完成任务上下文切换。

而在裸机程序中，编译器会根据函数调用约定和优化策略，决定是否需要在 ISR 中保存和恢复 R4 ~ R11。通常情况下，编译器会在 ISR 的函数入口处生成 PUSH 指令，将 R4 ~ R11 压入栈中，并在函数返回前生成 POP 指令，将其恢复。<br>

# 中断和异常
## 1. 中断和异常的区别
在 Cortex-M 中，**异常（Exception）是更大的概念，中断（Interrupt）属于异常的一种**。只要 CPU 因某个特殊事件偏离正常顺序执行流程，并转去执行对应的处理程序，都可以归入 Exception 机制。
- **异常（Exception）**：包括 CPU 内部异常、软件触发异常以及外部中断等。
- **中断（Interrupt）**：通常指由外设或外部事件产生的异步异常，例如 USART、TIM、DMA、EXTI 等 IRQ。
可以简单理解为：
```text
Exception
├── Reset
├── NMI
├── HardFault
├── MemManage
├── BusFault
├── UsageFault
├── SVCall
├── PendSV
├── SysTick
└── External IRQ
    ├── USART
    ├── TIM
    ├── DMA
    └── EXTI
```
因此：
> ***所有中断都属于异常，但并不是所有异常都是中断。***
### 1.1 同步异常与异步中断
异常可以根据是否与当前执行指令直接相关，分为同步和异步两类：
- **同步异常**：由当前正在执行的指令直接触发，例如执行 `SVC` 指令、非法指令、非法内存访问导致的 Fault 等。
- **异步异常**：与当前正在执行哪条指令没有直接关系，通常由外设事件产生，例如 UART 收到数据、定时器溢出、DMA 传输完成等，这类通常称为中断。
例如：
```text
执行 SVC 指令
    ↓
SVCall Exception
    ↓
同步异常
```
```text
UART 突然收到数据
    ↓
USART IRQ
    ↓
异步中断
```
### 1.2 Cortex-M 中的统一处理机制
虽然异常和中断的来源不同，但在 Cortex-M 中最终都统一通过 Exception 机制处理，包括：
- 根据异常号和中断向量表找到对应 Handler。
- Cortex-M 硬件自动保存部分寄存器现场。
- CPU 进入 **Handler Mode**。
- 执行对应的异常或中断处理函数。
- 通过 **EXC_RETURN** 执行异常返回。
- 硬件恢复现场，并继续之前的程序执行。
因此可以简单记为：
> ***异常描述的是 Cortex-M 对特殊事件的统一处理机制；中断通常特指其中由外设或外部异步事件触发的一类异常。***
